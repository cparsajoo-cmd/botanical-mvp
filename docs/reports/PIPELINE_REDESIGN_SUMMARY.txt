WHAT CHANGED
================================================================================

PREVIOUS PIPELINE (Broken):
  → Discovery
  → (optional) Screening
  → Generate case files
  ✗ No verification gate
  ✗ Hard-coded decisions in case
  ✗ Tests tested case, not engine
  ✗ No architecture preventing fabrication

REDESIGNED PIPELINE (Rigorous):
  → Discovery
  → Source Retrieval
  → Source Verification ← MANDATORY GATE
  → Evidence Extraction ← MUST MATCH SOURCE
  → Ready for Engine ← NO HARD-CODED LOGIC
  → Engine Evaluation ← REAL ENGINE INVOCATION
  → Integration Test Validation ← PRODUCTION ENGINE TESTS
  → Supervisor Approval
  
  No stage may be skipped.
  Pipeline halts automatically if any stage fails.


================================================================================
KEY ARCHITECTURAL IMPROVEMENTS
================================================================================

1. STATE MACHINE (Mandatory Sequential Stages)
   ────────────────────────────────────────────
   
   Before: Discovery → Generation (no explicit states)
   After:  8 mandatory states, one-way transitions
   
   States:
     1. DISCOVERED
     2. SOURCE_RETRIEVED
     3. SOURCE_VERIFIED (gating point)
     4. EVIDENCE_EXTRACTED
     5. READY_FOR_ENGINE
     6. ENGINE_VALIDATED
     7. TEST_VALIDATED
     8. SUPERVISOR_APPROVED
   
   Enforcement: Code validates each transition; skipping raises PIPELINE_HALT
   
   Benefit: Case cannot progress without completing each mandatory stage


2. SOURCE VERIFICATION MODULE (No Fabrication)
   ──────────────────────────────────────────────
   
   Before: Metadata was hard-coded (future-dated Cochrane ID)
   After:  Strict verification framework
   
   Required data:
     • BibliographicMetadata (complete, no abbreviations)
     • RetrievalRecord (method, date, accessed by whom)
     • ArchiveRecord (archive.org, PDF, or repo link)
     • EvidenceQuote (with exact locators)
     • VerificationRecord (signed by verifier, timestamp)
   
   Forbidden: Any field can be left empty, but NOT fabricated
   
   Enforcement: submit_verification() returns (is_verified, missing_items)
                Verification fails if ANY required field is missing or fabricated
   
   Benefit: Impossible to create unverified sources


3. REPORT VALIDATOR (Exact Metrics, Real Hashes)
   ──────────────────────────────────────────────
   
   Before: Reported 463 lines, actual file was 261 lines
           Reported "12 tests", file had 8 tests in one place
           SHA-256 hashes were placeholders
   
   After:  Automatic calculation, verification, no placeholders
   
   Calculated automatically:
     • Line counts (not approximated)
     • File sizes
     • SHA-256 hashes
     • Test method counts
     • Assertion counts
     • Test execution results
   
   Enforcement: Report generation FAILS if reported metrics don't match artifacts
   
   Benefit: No numerical inconsistencies possible


4. INTEGRATION TEST BUILDER (Real Engine Invocation)
   ────────────────────────────────────────────────
   
   Before: Tests verified hard-coded values in case object
   After:  Tests invoke REAL production engine
   
   Generated test structure:
     • Import production modules (assertion_vocabulary, applicability_check)
     • Feed case evidence to engine
     • Compare engine output to expected outcomes
     • Include negative-control tests (tests FAIL if engine wrong)
   
   Enforcement: Tests import and invoke real modules; cannot be circular
   
   Benefit: Tests validate engine, not case object


5. CASE OBJECT DESIGN (No Hard-Coded Decisions)
   ──────────────────────────────────────────────
   
   Before: Case contained:
             applicability["INDICATION_EVIDENCE"] = True (hard-coded)
             assertion_type = "SUPPORTS_INDICATION" (hard-coded)
   
   After:  Case contains ONLY:
             • Verified source metadata
             • Botanical scope
             • Evidence quotes with locators
             • Independent expected outcomes
             
           Case CANNOT contain:
             • Applicability logic
             • Assertion extraction logic
             • Confidence assignment logic
             • Any decision-making code
   
   Enforcement: Case validation fails if hard-coded logic detected
   
   Benefit: Decisions come from engine, not case


================================================================================
MANDATORY VERIFICATION GATES
================================================================================

Gate 1: SOURCE_NOT_FOUND
  Condition: Source document is not retrievable
  Action: PIPELINE_HALT
  Severity: Critical

Gate 2: SOURCE_NOT_VERIFIED
  Condition: Source metadata cannot be verified against official records
  Action: PIPELINE_HALT
  Severity: Critical

Gate 3: EVIDENCE_NOT_VERBATIM
  Condition: Evidence text doesn't support the claimed assertion
  Action: PIPELINE_HALT
  Severity: Critical

Gate 4: METADATA_FABRICATED
  Condition: Hard-coded decisions or fabricated metadata found
  Action: PIPELINE_HALT
  Severity: Critical

Gate 5: ENGINE_EVALUATION_FAILED
  Condition: Engine crashes or produces inconsistent output
  Action: PIPELINE_HALT
  Severity: Critical

Gate 6: TEST_INTEGRATION_FAILED
  Condition: Any integration test fails
  Action: PIPELINE_HALT
  Severity: Critical

Gate 7: REGRESSION_FAILED
  Condition: Any existing test fails
  Action: PIPELINE_HALT
  Severity: Critical

Gate 8: REPORT_VALIDATION_FAILED
  Condition: Reported metrics don't match artifacts
  Action: PIPELINE_HALT
  Severity: Critical

Result: Case cannot reach SUPERVISOR_APPROVED state if any gate fails

  Every source must be verified against official records.
  No metadata can be fabricated.

✓ EVIDENCE INTEGRITY

  Tests invoke real production engine.

✓ REPRODUCIBILITY
  Same verified source → same case (deterministic)
  Same case → same engine output (engine is deterministic)
  Same output → same test results (tests are deterministic)

✓ AUDITABILITY
  Every stage has explicit record (StateTransition, VerificationRecord)
  Timestamps on all records
  Verifier/retriever identity recorded
  All decisions traceable to source or engine

✓ IMPOSSIBILITY OF INVALID CASES
  Architecture prevents fabrication at multiple levels:
    - State machine (mandatory gates)
    - Verification module (no fabrication)
    - Case validator (no hard-coded logic)
    - Test builder (real engine invocation)
    - Report validator (exact metrics)

WHAT DOESN'T WORK ANYMORE (AND WHY)
================================================================================

Hard-coded Applicability:
  applicability["INDICATION_EVIDENCE"] = True
  ✗ Not allowed (would be caught by pipeline validation)
  ✓ Must be computed by engine

Fabricated Metadata:
  title="Cochrane Review for Ginkgo..."
  authors="Tan et al."
  publication_date="2026-03-15"
  ✗ Not allowed (verification module requires all fields verified or empty)
  ✓ Must come from verified source record

Paraphrased Evidence Labeled Verbatim:
  transformation_type="VERBATIM"
  [generic summary text]
  ✗ Not allowed (evidence extraction stage requires exact locators)
  ✓ Must be marked PARAPHRASED or have precise page/section numbers

Circular Tests:
  self.assertEqual(case.assertion_type, "SUPPORTS_INDICATION")
  ✗ Not allowed (integration test builder requires engine invocation)
  ✓ Must feed evidence to engine and validate output

Placeholder Metrics:
  Reported: "463 lines"
  Actual: 261 lines
  ✗ Not allowed (report validator calculates actual values)
  ✓ Must calculate from artifacts with SHA-256 verification
